# 타자 레이스 ⌨️

화면에 나오는 한글 글을 똑같이 쳐서 달리는 타자 경주입니다. 서버 없이 `index.html` 만 열면 돌아갑니다.

- 조작: 입력창에 위의 글을 **똑같이 따라** 칩니다(폰은 한글 키보드가 올라옵니다). 틀린 글자는 빨갛게 표시되고, 지워서 고쳐야 앞으로 나갑니다. 붙여넣기는 막혀 있습니다. `M` 소리.
- 규칙은 `logic.js`(DOM 없음), 화면·소리·입력은 `game.js`. 시험: `node --test`.

## 규칙
- 한 판은 속담·일상 문장 **3개**(공백으로 이어진 한 덩어리). 3 · 2 · 1 뒤에 시작하고, **맞게 친 글자 수**가 달린 거리입니다(앞에서부터 맞은 글자까지만 셈, 지우면 줄어듦). 맨 끝까지 똑같이 치면 결승선입니다.
- 컴퓨터 주자는 쉬움 3명(분당 약 48 · 68 · 90글자), 보통 4명(약 85 · 120 · 155 · 195글자). 사람처럼 빨랐다 느렸다 하고 가끔 멈칫합니다. 내가 들어온 뒤 8초가 지나거나 모두 들어오면 끝납니다(못 들어온 주자는 달린 거리 순).
- 결과: 순위 · **속도(글자/분)** · **정확도**(= 글자 수 ÷ (글자 수 + 틀린 횟수)) · 틀린 횟수. **보통에서 낸 가장 빠른 속도**가 최고 기록입니다(쉬움은 저장 안 함). 쉬움은 짧은 글(8~20자), 보통은 긴 글(16~34자)입니다.

## 한글 입력 판정에서 조심한 점
- 한글은 키를 하나씩 누르는 중에 글자가 **조합**되므로(`ㅂ` → `바` → `반`), 마지막 글자가 아직 조합 중이면 목표 글자가 될 수 있는 중간 모양인지(자음·모음 순서로 풀어서 앞부분인지)를 봅니다. `과` 를 칠 때의 `고`, `닭` 을 칠 때의 `달`, 그리고 `하나` 를 치는 도중 받침이 다음 글자로 넘어가기 전의 `한` 도 틀린 것으로 치지 않습니다.
- 두벌식 입력기를 흉내 낸 시험으로 **모든 문장(42개)을 키 하나씩 누르는 모든 중간 상태**에서 확인했습니다: 틀린 횟수 0, 마지막에 완주.
- 실제 폰 키보드(천지인·나랏글 등 다른 한글 방식)에서의 조합 모양은 확인하지 못했습니다.

## 균형
- 내 속도를 고정하고 200판씩 모의: 쉬움에서 100글자/분이면 1등 100%, 60글자/분이면 2등 안 30%. 보통에서 150글자/분은 2등 안 69%, 200글자/분은 1등 91%, 260글자/분은 100%. 대략 PC 로 한글을 치는 사람은 분당 150~300글자, 폰은 80~160글자로 봤습니다.
- **사람의 실제 속도와 체감 난이도는 측정하지 못했습니다.**

## 참고한 것과 제가 정한 값
- 「글을 따라 치며 달리는 타자 경주」라는 널리 알려진 형식을 따랐습니다. 문장은 흔한 속담과 제가 쓴 짧은 일상 문장입니다. 주자 속도와 길이는 제가 정한 값이고, 온라인 대전은 없습니다.
